# 兼容性与已知限制

首版开发已经结束；以下是交付范围和验证边界，不是要求使用者完成的开发任务。

| 组件 | 已有证据 | 边界 |
| --- | --- | --- |
| Linux Sender | Herdr 0.8.2 / socket protocol 20 | 不承诺其他协议版本；不采集 Herdr 外部 Agent |
| Android/Termux Receiver | Node.js 26 环境部署、真灯联调 | 项目要求 Node.js >=24；长期锁屏与厂商后台限制未做持续验收 |
| ESP32 单颗 RGB | classic ESP32 32E 实物，IO25/26/27、共阴、每路 220Ω | 不直接适用于 C3/S3 或其他引脚布局 |
| Windows | 固件编译/设备操作流程及跨平台 Node 源码 | Windows 作为 Receiver 的完整链路未单独验收 |
| WLED | Receiver preset 请求及模拟输出 | 真实 WLED/WS2812B 硬件不属于本次实物验收 |

## 状态不等同于任务文字

Herdr 的 done 表示后台完成尚未查看；停留在当前页面时，完成可能直接进入 idle。blocked 取决于 Herdr 能否识别必要输入/授权界面；普通提问不一定会被识别。本项目不读取终端正文自行猜测状态。

多个会话按 blocked > working > unknown > done > idle 聚合。收到上游采集异常时总体 unknown；不能把采集失败当空闲。用户整体验收已完成，但没有额外保存每一种多 Agent 组合、端到端延迟或长时间稳定性的测量数据。

## 故障恢复

- Sender 正常每 5 秒发送心跳；Receiver 默认 15 秒无新快照时变 unknown。
- 按键 Demo 不持续发心跳，停留超时会变黄；done 没有独立的自动熄灭计时器。
- 手机进程停止/暂停，而热点仍在时，灯可能保留旧颜色。设备没有“长时间无 HTTP 请求”看门狗，因为相同状态正常情况下不会重复发送设备请求。
- ESP32 重启后初始 unknown。Receiver 若缓存了成功输出，不保证立即补发；可以重启 Receiver 或切换状态，并核对热点分配的设备 IP。
- 固件保存在 Flash，断电不丢；热点密码也编入镜像，带真实密码的固件不能作为公开发行包。
- 固件支持 Wi-Fi 断线处理，但没有 OTA、完整 WLED API、设备端鉴权或状态持久化。

## 网络与运行方式

Receiver 与设备 HTTP 接口没有应用层认证。source_id 是来源标识，不是密钥；仅在受控私网使用，按需限制 Tailscale 访问，不做公网端口转发。不要监听 0.0.0.0。

本版采用手动前台启停，不安装 systemd、自启或崩溃重启服务。开发代码完成不代表后台运行由系统保证。供电设备是否因低负载关机也需按自己的硬件确认。
