# T-005 手机接收可行性验证

> 历史验证记录：地址、用户名和部署路径已替换为示例；日期、测试结果及限制保留。记录描述当时状态，当前首版验收见 [T-010](T-010.md)。


日期：2026-09-11

## 环境与范围

- 手机：Android 测试手机，Tailscale IPv4 `100.64.0.10`。
- 服务器 Tailscale IPv4：`100.123.197.98`。
- 手机 Termux 运行单文件 Node.js Receiver 探针；不要求 ESP32 或真实 WLED。
- 用户在本次短时探针中明确允许手机临时监听 `0.0.0.0:8787`，探针设自动结束；正式 Receiver 仍禁止通配监听。

## 实际过程

1. 服务器只在自身具体 Tailscale IP 的 8790 端口临时提供单个探针文件，手机通过 `curl` 下载成功。
2. Termux 启动 `termux-receiver-probe.mjs`，手机本机健康检查可用。
3. 手机开启 Tailscale 的 LAN 访问并保持热点开启；服务器对手机 Tailscale 节点的 ping 约 74ms。
4. 服务器绕过本机 HTTP 代理执行健康检查，收到 `{"status":"ok","probe":"termux"}`。
5. 服务器发送正式 v1 格式的 working、blocked、done，三次均返回 `disposition=applied`。
6. 用户锁屏约 20 秒；服务器以 10 秒间隔再次发送 working、blocked、done，三次均成功。
7. 测试窗口结束后发送 idle，返回 `disposition=applied`，证明链路仍可恢复使用。

## 结论

- 服务器经 Tailscale 到 Android/Termux Receiver 的入站 HTTP 可行。
- 本次配置下，手机热点与 Tailscale 可以同时保持，短时锁屏 20 秒未中断 Receiver。
- Linux 服务器的 `curl` 访问 Tailscale 地址需要 `--noproxy '*'`；Node.js `fetch` 直连成功。该现象是服务器代理环境注意事项，不是手机端口权限问题。
- 8787 高于特权端口范围，不存在低端口绑定问题。

## 限制

- 仅证明约 20 秒锁屏，不代表长时间后台稳定；T-010 仍需按演示时长验证。
- 本次未安装或调用真实 WLED，未验证手机热点到 ESP32。
- 临时文件下载服务已停止；手机探针由用户按 Ctrl+C 停止或到时自动结束。
