# T-007 聚合与 Herdr 发送端验证

日期：2026-09-11

## 范围

实现独立的 Herdr 采集与聚合发送进程。真实接口事实沿用 T-003 对 Herdr 0.8.2 / protocol 20 的样本；本轮用本机 schema、Unix socket 模拟器、内存 Herdr API 和回环 Receiver 验证生产逻辑。当前 Agent 没有读取用户终端正文或真实会话内容。

## 实现证据

- `server/herdr-api.mjs`：校验 pong 中的 protocol 20，封装 `agent.list`、`agent.get` 和生命周期/单 pane 状态订阅。
- `server/herdr-collector.mjs`：生命周期订阅、两次 list reconciliation、逐 pane 订阅、历史事件当前状态核对、事件积压上限、断线退避与完整重连。
- `shared/aggregation.mjs`：业务五态与采集健康分离，按 `blocked > working > unknown > done > idle` 聚合；release/exit/close 后删除会话。
- `server/snapshot-sender.mjs`：每进程 UUID、严格递增 sequence、5 秒心跳、2 秒请求超时、同 sequence 有界重试，以及新快照替换旧重试。
- `server/app.mjs`、`scripts/run-sender.mjs`：组合采集与发送生命周期，提供跨平台 Node.js 入口。
- 默认 Receiver 目标按用户当前演示环境设为 vivo-phone `100.91.207.103:8787/v1/state`；仍可通过自定义配置覆盖。

发送给 Receiver 的快照只含协议版本、配置来源 ID、随机进程实例、序号、时间、总体状态、cause 和各状态数量；不含 Agent 名称、pane/workspace ID、工作目录、终端正文或会话引用。

## 自动验证

`npm test`：40 项通过、0 项失败。T-007 新增覆盖：

- 本地 Unix socket 对 protocol 20 pong 的接受及其他版本拒绝。
- 初始化、健康零会话、采集失败/不兼容与多会话优先级。
- 第一次/第二次 agent.list 之间新增 pane 的启动竞态。
- 历史 release 事件在 Agent 仍存在时不误删；`pane_not_found` 时清除。
- 状态订阅、release/close、订阅断线进入 unknown、重连后完整快照替换旧缓存。
- 同 sequence 有界重试、新状态替换旧重试、递增心跳。
- 模拟 Herdr 的 working → blocked → release/idle → disconnect/unknown 经真实 HTTP 到达 Receiver。
- Herdr 请求或订阅在确认/响应前关闭时立即失败，不等待完整超时。

`npm run check` 与 `git diff --check` 通过。
