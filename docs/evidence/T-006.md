# T-006 Receiver 与模拟 WLED 验证

日期：2026-09-11

## 范围

本次只验证本机回环 Receiver、协议逻辑、dry-run 和本地模拟 WLED。没有绑定 Tailscale 地址，没有连接 Android、Windows、ESP32 或真实 WLED。

## 实现证据

- `shared/protocol.mjs`：v1 字段、来源、UUID、序列号、RFC 3339 UTC、状态/cause/counts 一致性校验。
- `receiver/state-store.mjs`：重复、冲突、乱序、新 instance、retired instance、15 秒本地单调时钟超时及恢复。
- `receiver/server.mjs`：`POST /v1/state`、4096-byte 上限、Content-Type、错误响应和 `GET /health`。
- `receiver/wled-output.mjs`：preset 映射、请求超时、有界重试、最新状态替换旧重试，以及由后续心跳触发的恢复。
- `scripts/run-receiver.mjs`：跨平台 Node.js 启停入口；默认读取 `receiver/config.example.json`。

WLED 调用按[官方 JSON API](https://kno.wled.ge/interfaces/json-api/)实现：向 `/json/state` POST 状态对象，preset 使用 `ps` 字段。

## 自动验证

`npm test`：23 项通过、0 项失败。覆盖：

- 五态聚合优先级、零 counts、unknown 与异常 cause。
- 配置默认回环、禁止通配监听、来源和 preset 约束。
- HTTP 成功、415、413、403、400、409 和未启用 Demo 的 404。
- 心跳刷新不重复应用成功 preset；超时进入 unknown；新 sequence 恢复。
- 本地 HTTP 模拟 WLED 收到 `/json/state` 和正确 `ps`；失败有界重试，后续心跳恢复；新状态取消旧状态后续重试。

`npm run check` 和 `git diff --check` 通过。

## 手动 dry-run

运行 `npm run receiver` 后实际输出初始 `unknown` preset 5，并监听 `127.0.0.1:8787`。向 `/v1/state` 发送合法 done 快照后返回 `disposition=applied`，`/health` 显示 done；停止心跳 15 秒后 dry-run 输出 unknown preset 5。进程已用 Ctrl+C 停止。
