## 实现

firmware/include/beacon.h：固定 preset 1～5 的严格无分配解析、五态灯效、共阳/共阴 PWM 变换、状态切换去重及 unsigned 时间差。firmware/src/main.cpp：STA Wi-Fi、周期重连、独立 HTTP 任务、原子状态邮箱、三路 PWM、开机/断网 unknown。firmware/include/config.example.h：空凭据、禁用输出、GPIO=-1；需要本机 config.local.h 才能按实际接线启用。

POST /json/state 与现有 Receiver 编码兼容，GET /health 仅报告软件状态。请求长度读取前上限 64 bytes，不支持的正文/类型不更新状态。没有设备端心跳超时、OTA 或配置网页；不声称完整 WLED API 兼容。

## 依赖与构建

项目本地 Python venv 中安装 PlatformIO Core 6.1.18；缓存位于 .local/platformio，无全局安装。firmware/platformio.ini 固定 espressif32 6.10.0、framework-arduinoespressif32 3.20017.241212（Arduino 2.0.17），实际工具链 xtensa 8.4.0+2021r2-patch5、esptool 4.5.1。使用框架自带 WiFi、LEDC、ESP-IDF HTTP server，不新增固件第三方 JSON 库。Node package-lock 无依赖变更。

命令：`PLATFORMIO_CORE_DIR="$PWD/.local/platformio" .local/firmware-tools/bin/pio run -d firmware`。

最终构建 SUCCESS；RAM 43520 / 327680 bytes（13.3%），Flash 759593 / 1310720 bytes（58.0%）。生成 firmware/.pio/build/esp32dev/firmware.bin 和对应 ELF/bootloader/分区文件，均未刷机。默认配置不输出 GPIO，也不含真实热点凭据。

首次安装构建时 esptool 4.5.1 在本机 Python 下提示 finally-return SyntaxWarning，未导致构建失败；未修改第三方工具源码。

## 测试

- `npm run test:firmware`：使用 g++ C++11、-Wall/-Wextra/-Werror 和 ASan/UBSan 构建并运行。覆盖五个编号、越界编号、重复/额外字段、错误类型、小数/指数、截断输入、超长正文、NUL 和尾随垃圾；失败保持原状态。
- 灯效验证包含呼吸端点、闪烁边界、done 无计时结束、极性反转、重复状态不重置时间、Wi-Fi unknown 覆盖与恢复、millis 回绕和禁用 GPIO。
- 同命令通过回环 HTTP 使用真实 Receiver WledOutput 发出五态，再由同一固件 C++ 解析器读取实际正文，五态全部匹配。没有以 JS 重写固件逻辑来代替验证。
- `npm test`：48 项 Node 业务测试通过。固件验证脚本命名 verify-firmware.mjs，避免 Node 自动发现把本机 C++ 工具链强加给原有 Node 测试。
- `npm run check`、git diff --check、Markdown 相对链接及任务表一致性检查通过。
