## 结果

- 手机地址 100.64.0.10，OpenSSH 8022；用户 TERMUX_USER。ED25519 主机指纹与用户在手机上提供的 （主机指纹已脱敏） 一致。连接使用严格主机校验与指定项目密钥；未更改全局 SSH 配置。
- 手机 Node v26.3.1，npm 11.17.0。部署前未发现 Node Receiver 进程，无需停止旧探针。
- SCP 传入运行包和 SHA-256 文件；手机 sha256sum -c 返回 OK。
- 安装路径 `~/agentbeacon/releases/receiver-example`，复制手机示例为 receiver/config.json，保留具体 Tailscale IP、dryRun=true、demoEnabled=false。
- 使用 Node spawn 的 detached 进程启动，stdio 指向 receiver.log，PID 写入 receiver.pid。初始 PID 16384；后续操作必须核对 PID 是否仍对应本项目命令。SSH 退出后，从另一连接确认 Receiver 仍在运行。
- 服务器执行 `node scripts/probe-phone.mjs --url http://100.64.0.10:8787/v1/state --states working --interval 0`，返回 `OK working sequence=1 disposition=applied`。
- `/health` 返回 status=ok、state=working、timed_out=false、dry_run=true、demo_active=false。手机日志记录初始化 unknown/preset=5 和 working/preset=2。

硬件未到货，真实 WLED 地址和 preset 尚未确定，不能向示例占位地址发送请求。收到实际硬件配置后修改 wledBaseUrl/dryRun 并重启，进行 T-010。后台进程未配置自动重启、wake-lock 或开机自启，未验证锁屏长期运行。部署留下 Receiver 进程供后续使用；未启动真实 Herdr Sender。

进入上述目录后 `npm start` 可前台运行。停止现有实例前，用 `ps -p 16384 -o pid,args`（按 receiver.pid 当前值替换）确认命令确实为本项目，再发送 SIGTERM；不能同时启动两份抢占 8787。日志为 receiver.log，未设置轮转。

本机 `.local/ssh/termux` 是项目私钥，`.local/ssh/known_hosts` 是核对后的主机公钥记录；.local 已加入 .gitignore。不将私钥收入运行包、文档或 Git。

## 用户前台复验
