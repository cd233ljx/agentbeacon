# T-012A：手机 Receiver 运行包与使用说明

日期：2026-09-12；负责人：Codex。范围：可独立传输的运行包、手机配置示例、安装/启停/日志/回滚和验收说明。无新增第三方依赖，无业务逻辑变更，无手机部署或常驻服务变更。

## 交付

- `npm run package:receiver`：临时目录中按白名单复制 9 个运行/配置文件，加入 README 和最小 package.json；通过 npm pack 生成 dist 中的 tgz 和 SHA-256 文件。结束清理临时目录。
- 手机示例使用上次实测地址 100.91.207.103，dryRun=true、demoEnabled=false；安装时必须核对当前 IP。真实硬件地址仍是占位。
- [运行指南](../termux-receiver.md)：手机传入、校验、独立目录解包、替换探针、配置、启动/停止、日志、后台边界、五态/超时/恢复、WLED 切换和回滚。
- 明确区分按键 TUI 的一次性正式快照与显式 HTTP Demo，避免将 TUI 停留后的超时误判为异常。

## 实际验证

环境：本机 Linux，Node v24.18.0，npm 11.16.0。

1. `npm run package:receiver` 成功；实际解包检查共 11 个文件，不含 server 目录、本机 config.json 或日志。按 SHA-256 文件比对产物通过。
2. 使用 Python 临时目录解包，将配置改为回环动态端口，并连接本机临时 HTTP WLED 模拟器。运行包目录内 `npm start` 独立启动成功，不安装依赖、不引用仓库文件。
3. 向 `/v1/state` 发送包含 UUID、递增 sequence、合法 counts 的五态快照，逐次检查 `/health`；模拟 WLED 接收到 preset 序列 `[5,1,2,3,4,5]`（首个 5 为初始化）。
4. 连续发送 done，第二次不重复应用 preset；保持实际默认 receiverTimeoutMs=15000，等待健康接口 timed_out=true/state=unknown，发送 working 后恢复且 timed_out=false。完整 preset 序列为 `[5,1,2,3,4,5,4,5,2]`。
5. 发送 SIGINT 停止 npm 启动的进程组；再用文档中的 Node 直接启动方式测试 dry-run，health 返回 dry_run=true，日志含 unknown/preset=5。SIGINT 后 Node 退出码为 0。
6. `npm test`：48 项通过、0 失败。`npm run check` 通过。`git diff --check`、Markdown 本地链接检查通过。

首次临时验证脚本用了非 UUID 的 instance_id，被正确返回 HTTP 422；修正测试数据后完成上述验证，未修改业务代码。模拟 HTTP 服务及测试 Receiver 已全部停止，临时解包目录已清理。
